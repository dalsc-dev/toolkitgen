Understanding Binary and Hexadecimal

To understand what a binary file viewer does, we first need to understand how computers store data. Computers work with binary (base-2) numbers - strings of 0s and 1s. Each 0 or 1 is called a bit, and eight bits make a byte.

Bytes can represent values from 0 to 255. While binary is what computers actually use, hexadecimal (base-16) is the human-readable format that is most practical for viewing binary data. Each hex digit represents four binary bits, so two hex digits represent one byte perfectly.

Common File Format Signatures

File headers are sequences of bytes at the beginning of files that identify the file format. These "magic numbers" allow programs to identify file types regardless of file extensions.

Hexadecimal Fundamentals

Hex Number System

Hexadecimal uses 16 symbols: 0-9 and A-F. Each position represents a power of 16. The rightmost digit is ones (16 to the 0), the next is sixteens (16 to the 1), and so on.

Hex values are typically written with a "0x" prefix (0xFF = 255) or an "h" suffix (FFh = 255) to indicate hexadecimal notation.

Converting Between Systems

Converting between decimal, binary, and hexadecimal is a useful skill:

  • Decimal to Hex: Divide by 16, track remainders
  • Hex to Decimal: Multiply each digit by its positional value
  • Binary to Hex: Group 4 bits, convert each group
  • Hex to Binary: Convert each hex digit to 4 bits

Common Hex Values

Familiarize yourself with common hex values:

  • 0x00: Null byte, often padding
  • 0xFF: Maximum byte value, often used for white in images
  • 0x20: Space character
  • 0x0A: Line feed (Unix newline)
  • 0x0D: Carriage return

Understanding Data Types in Hex

Integers

Integers are stored in various sizes:

  • Byte: 8 bits, 0-255 (unsigned) or -128 to 127 (signed)
  • Word: 16 bits, 0-65535 (unsigned)
  • Dword: 32 bits, 0-4.3 billion (unsigned)

Multi-byte integers may be stored little-endian (least significant byte first) or big-endian (most significant byte first).

Floating Point Numbers

Floating point numbers (decimals) follow IEEE 754 standard. Single precision (float) uses 32 bits, double precision (double) uses 64 bits.

Hex views of floating point data look like random bytes - specialized tools are needed to interpret them correctly.

Strings

Strings are sequences of character bytes. Common encodings include:

  • ASCII: One byte per character, 128 possible characters
  • UTF-8: Variable length, backward compatible with ASCII
  • UTF-16: Two bytes per character, common in Windows

Endianness Explained

Little Endian

Little endian stores the least significant byte first. For the value 0x12345678, bytes are stored as 78 56 34 12. Intel and AMD processors use little endian.

Little endian makes sense because it simplifies comparing multi-byte values - lower addresses hold lower values.

Big Endian

Big endian stores the most significant byte first. For 0x12345678, bytes are stored as 12 34 56 78. Network protocols typically use big endian (called "network byte order").

Big endian matches how humans read numbers left-to-right, making it intuitive for debugging.
